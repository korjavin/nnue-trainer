# NNUE v3.1b — runtime path: NNUEv3Accumulator + NNUEv3Evaluator + EVAL=NNUEV3 GoBot leaf

## Overview

Bead `nnue-trainer-aov`. Make the engine able to actually *evaluate* with the v3 features whose
capacity was just proven (`d4a.6.1`, held-out R² ≈ 0.94–0.98, merged in #94).

This is the last piece before a strength number: it turns `nnue_v3_weights.json` into a leaf
evaluation the GoBot search can call, so `d4a.6.2` can run the gauntlet against GoBot and against
the hand-tuned clone.

```
eval_v3(board, stm) = bias + Σ_{f active} weight_f      // exactly 144 active features
idx(r, c, state)    = (r * 12 + c) * 8 + state          // 1152 dense slots
```

**Why this is much simpler than the v2 equivalent it mirrors:**

- **No dictionary.** v2 needed a mined `PatternDictionary`, signature strings, hash lookups, a
  promotion threshold and `-1` miss handling. v3 indexes a dense array directly. None of that
  machinery is needed or wanted here.
- **No score scale.** v2 output a WDL-ish scalar and needed `NNUEV2_SCALE` to map it into score
  units — an entire bead (`d4a.4.1`) went into sweeping it. v3 was ridge-fit **against hand-tuned
  eval values**, so its output is already in hand-tuned score units (holdout MAE 1230 on a ±30000
  label). **Do not add a scale knob.** If one ever seems necessary, that is a signal something is
  wrong with the fit, not a knob to tune.
- **Full recompute is fine.** 144 array reads and adds per evaluation. Do NOT build incremental
  updates in this bead; add them only if a benchmark shows the leaf is the bottleneck.

## Context (from discovery)

Branch: `v3-runtime-leaf`, off `master`. **Merge target: master.**

- `nnue_v3_weights.json` (repo root, merged in #94) — `meta` carries `bias`, `lambda`, `top_n`,
  `n_features_total`, `r2_holdout`, corpus provenance (`games_used`, `positions_total`, …), and
  `weights` maps `"<feature_index>" -> weight` for all 1152 slots.
- `src/main/java/com/engine/nnue_trainer/train/V3FeatureMiner.java` — owns the canonical index:
  `BOARD = 12`, `STATES = 8`, `idx(r,c,state) = (r*BOARD + c)*STATES + state`. **Reuse this
  definition; do not restate the arithmetic in a second place.** Extract it if that is cleanest.
- `src/main/java/com/engine/nnue_trainer/v2/PatternContract.java` — `getSymbol(Cell, int stmOwner)`
  returns the perspective-normalized state (`EMPTY=0 … FORTIFIED_OPPONENT=7`; `OUT_OF_BOUNDS=8`
  cannot occur for on-board cells).
- `src/main/java/com/engine/nnue_trainer/v2/NNUEv2Evaluator.java` — the shape to mirror for
  loading: `DEFAULT_WEIGHTS` path constant, static `load(Path)`, instance `evaluate(...)`.
- `src/main/java/com/engine/nnue_trainer/search/gobot/GoBotSearcher.java` — the leaf wiring to
  mirror: `enum LeafEval { HAND_TUNED, NNUE, NNUEV2 }`, the immutable `LeafConfig` snapshot,
  `configureDefaultLeafEvalV2(mode, evaluator)`, `restoreDefaultLeafEval(prev)`, and the
  `leafEval(state)` branch at ~line 594 which queries from the leaf's own mover and negates to the
  root's perspective.
- `src/main/java/com/engine/nnue_trainer/search/SearchEngine.java` — the `EVAL=` env hook, the
  lazy `volatile` shared-evaluator load with a warn-once failure fallback, and `setUseNnueV2Eval` /
  `setNnueV2Evaluator` test hooks.
- `python/v3/fit_capacity.py` — the fitter whose predictions the Java runtime must reproduce.

Environment: Java 17 + Maven (`./mvnw`), Jackson, numpy available. **No new dependencies.**

### Task 2: NNUEv3Evaluator — load weights, evaluate

- [x] create `src/main/java/com/engine/nnue_trainer/v3/NNUEv3Evaluator.java` with a
      `DEFAULT_WEIGHTS = Path.of("nnue_v3_weights.json")` constant, a static `load(Path)`, and an

- [x] evaluate as `bias + Σ weight[idx]` over the accumulator's active indices — no scaling, no
      squashing, no clamping beyond what the leaf needs for mate bounds
- [x] write tests: a known small weights file evaluates to a hand-computed score; malformed inputs
      (missing key, wrong type, NaN weight, out-of-range index) each throw on load

## Technical Details

**Score units**: hand-tuned eval units, directly. Holdout MAE was 1230 against labels spanning
roughly ±30000. No scaling.

**Perspective**: `evaluate(board, stm)` is STM-relative (positive = good for `stm`), matching both
`HandTunedEval.staticEval` and the training labels. The leaf negates to the root's frame exactly as
the v2 branch does.

**Board size**: 12x12 only. The accumulator rejects other sizes; the `SearchEngine` branch falls
back to hand-tuned so play on other sizes is unaffected.

**Weights file**: repo-root `nnue_v3_weights.json`, overridable by env (`NNUEV3_WEIGHTS`) in the
same spirit as `NNUEV2_WEIGHTS`.
