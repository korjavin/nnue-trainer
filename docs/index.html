NNUE Trainer for the Virus Game

A running experiment in teaching a neural evaluator to out-play a hand-written one — with every success and failure measured and written down.

The hypothesis

The Virus game is a 12×12 territory game where each turn grants three actions. Our bot plays live on the server, driven by a classic alpha-beta search whose leaf evaluation is a hand-tuned function ported from an earlier Go bot. The hypothesis of this project:

A small neural network, trained on the bot's own games, can replace the hand-tuned evaluation — first matching it (distillation), then exceeding it by learning from deep search results that no static function can encode.

What is NNUE?

NNUE ("efficiently updatable neural network") is the technique that made neural evaluation practical inside alpha-beta search engines like Stockfish. The trick is architectural discipline:

  • Sparse binary features. A position is encoded as a set of active feature ids — here, one per board cell: (row, col, cell-state), 144 active out of 1152 possible, always from the side-to-move's perspective.
  • A shallow net. One hidden layer. The first layer is never a dense matrix multiply — it's a sum of 144 weight columns, cheap enough to run at hundreds of thousands of leaf evaluations per second inside the search.
  • Training on search-shaped data. The evaluation's only job is to order the children of one position so search prunes correctly. Our training loss is a ranking loss over sibling moves, not just regression.

The story so far

v1 — whole-board baseline

A simple whole-board net. Weak, but it later beat v2 21–3 — the first hint that position-aware, board-scale features matter more than clever locality.

v2 — local 5×5 patterns (failed, instructively)

Sparse counted 5×5 pattern features, frequency-promoted dictionary, board-size independent. Lost the gauntlet 0–24 against the hand-tuned eval despite excellent offline metrics. Root cause (see the autopsy above): frequency selects common features, and common ≠ informative.

v3 — whole-board, position-aware, eval-distilled (current)

Fix 12×12. One feature per (cell, state). Select by eval-discrimination, never frequency. First distill the hand-tuned static eval (capacity proof: held-out R² ≈ 0.93–0.98), then swap labels to deep-search values to try to exceed it.

Where v3 stands (honest numbers)

Training labelsGauntlet vs hand-tuned, depth 3Meaning
Static eval (distillation) 24.3% ± 2.1 400 games, disjoint openings. The distillation ceiling: offline metrics kept improving, strength never followed.
Depth-2 search values 28.5% ± 2.3 400 games. Same net, same features — only the label oracle got deeper.
Depth-3 search values 44.3% ± 2.5 400 games — the closest v3 has come to parity (50%). But it is brittle: the same net at search depth 4 collapses to 9.0% ± 2.0, and at equal time (250 ms/move) to 27.0% ± 3.1.

The label-depth ladder vindicated the label hypothesis at its sweet spot: search-derived labels are the first lever that moved the gauntlet at all, twenty points' worth. And it exposed the wall: the gain exists only at the training distribution's search depth. Deeper search steers into positions the labels never covered, where the net's errors are large — every net measured here gets weaker when the search gets deeper. That failure mode has a name — distribution shift — and a known cure: train on the positions search actually visits. Self-play RL (MCTS with a learned policy and value net) is implemented and awaiting its first generation; it is the successor, not another patch on distillation.

Method notes

  • Every strength claim needs games. Small gauntlets lie: at 24 games the standard error is ±10 points. We run 400+ games with disjoint opening seeds.
  • Cross-language parity is pinned. The net trains in PyTorch and runs in Java; a committed fixture asserts both produce identical scores on real positions.
  • Frames matter. The costliest bug so far: training labels computed from the wrong player's perspective on 47% of positions — invisible offline, catastrophic in play.
